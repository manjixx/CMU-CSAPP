

# 📚 x86-64 函数调用、寄存器、栈与虚拟内存完全指南  
*基于 System V AMD64 ABI（Linux/macOS 标准）*

---

## 🏗️ 一、寄存器分类与调用约定（System V AMD64 ABI）

### 1.1 寄存器角色划分

| 类型 | 寄存器 | 保存责任 | 用途说明 |
|------|--------|----------|----------|
| **Caller-saved**<br>（易失性） | `%rax`, `%rcx`, `%rdx`, `%rsi`, `%rdi`, `%r8`–`%r11` | 调用者负责保存 | 用于参数传递、临时计算；函数调用后内容可能被覆盖 |
| **Callee-saved**<br>（非易失性） | `%rbx`, `%rbp`, `%r12`–`%r15` | 被调用者负责保存 | 用于长期存储；函数返回时必须恢复原始值 |
| **特殊用途寄存器** | `%rsp`（栈指针）<br>`%rip`（指令指针） | 硬件/系统维护 | `%rsp` 指向栈顶；`%rip` 指向下一条指令地址 |
| **浮点/向量寄存器** | `%xmm0`–`%xmm7` | 易失（caller-saved） | 传递浮点参数、返回浮点值 |
| | `%xmm8`–`%xmm15` | 易失 | 用于浮点/向量临时计算 |

> 💡 **关键原则**：所有函数共享同一套物理寄存器，通过 **保存/恢复机制** 实现逻辑隔离。

### 1.2 “易失”与“非易失”的本质：调用者视角的可靠性

术语“易失”（volatile）与“非易失”（non-volatile）完全从调用者（Caller）的视角定义，描述的是函数调用后寄存器值是否可靠：

- 易失寄存器（Caller-saved）
  - 调用者视角：调用函数后，这些寄存器的值“可能就没了”（被覆盖），如同挥发 → 易失。
  - 原因：被调用者可随意使用这些寄存器，无需恢复。
  - 责任：若调用者希望保留值，必须自己提前保存（如压栈）。
- 非易失寄存器（Callee-saved）
  - 调用者视角：调用函数后，这些寄存器的值“一定还在”，和调用前完全一致 → 非易失。
  - 原因：被调用者若使用这些寄存器，必须在返回前恢复原始值（通常通过 push/pop）。
  - 责任：保存与恢复由被调用者承担，对调用者透明。

---

### 1.3 参数传递规则

#### 整数/指针参数（前6个）
| 参数序号 | 寄存器 |
|--------|--------|
| 1st    | `%rdi` |
| 2nd    | `%rsi` |
| 3rd    | `%rdx` |
| 4th    | `%rcx` |
| 5th    | `%r8`  |
| 6th    | `%r9`  |

#### 浮点参数（前8个）
| 参数序号 | 寄存器 |
|--------|--------|
| 1st    | `%xmm0` |
| 2nd    | `%xmm1` |
| ...    | ... |
| 8th    | `%xmm7` |

#### 超出寄存器数量的参数
- **从右向左压入栈中**（即最后一个参数最先压栈）
- 栈上参数对齐到 **8字节边界**
- 被调用函数通过 `%rbp + 偏移` 或 `%rsp + 偏移` 访问

> ✅ 示例：`func(a, b, c, d, e, f, g)`  
> - `a`→`%rdi`, `b`→`%rsi`, ..., `f`→`%r9`  
> - `g` 压入栈，位于 `8(%rsp)`（因为 `call` 已压入返回地址）

---

### 1.4 返回值规则

| 返回值类型 | 使用寄存器 |
|------------|-----------|
| ≤64 位整数 / 指针 | `%rax` |
| 32 位整数 | `%eax`（`%rax` 低32位） |
| 16 位整数 | `%ax` |
| 8 位整数 | `%al` |
| 128 位结构体（如 `__int128`） | `%rax`（低64位） + `%rdx`（高64位） |
| 浮点数（`float`/`double`） | `%xmm0` |
| 大结构体（>16字节） | 调用者分配内存，**首参数隐式传地址** |

> ⚠️ 注意：C 语言中返回大结构体时，编译器会自动插入隐藏的第一个参数（指向返回缓冲区的指针）。

## 🔄 二、函数调用全流程详解

### 2.1 调用方（Caller）职责

1. **准备参数**：放入对应寄存器或压栈
2. **保存 caller-saved 寄存器**（如需在调用后继续使用）
3. **执行 `call target`**：
   - 将下一条指令地址（返回地址）压栈
   - 跳转到 `target`
4. **调用返回后**：
   - 清理栈上参数（若使用）
   - 恢复 caller-saved 寄存器
   - 读取返回值（`%rax` 或 `%xmm0`）

```asm
; 调用 printf("%d %s", num, str)
main:
    mov    $format_str, %rdi     ; 第1参数：格式字符串
    mov    $42, %rsi             ; 第2参数：整数
    mov    $hello_str, %rdx      ; 第3参数：字符串指针

    ; 若 r10/r11 有重要数据，需保存
    push   %r10
    push   %r11

    call   printf                ; call 压入返回地址并跳转

    pop    %r11                  ; 恢复
    pop    %r10

    mov    %eax, result          ; 返回值（打印字符数）
```

---

### 2.2 被调用方（Callee）职责

1. **函数序言（Prologue）**：
   - 保存 `%rbp`
   - 建立新帧指针：`mov %rsp, %rbp`
   - 保存 callee-saved 寄存器（如 `%rbx`, `%r12` 等）
   - 分配局部变量空间：`sub $N, %rsp`
2. **函数体**：
   - 使用寄存器/栈访问参数与局部变量
3. **函数尾声（Epilogue）**：
   - 释放局部空间：`add $N, %rsp`
   - 恢复 callee-saved 寄存器
   - 恢复 `%rbp`
   - 执行 `ret`（弹出返回地址并跳转）

```asm
my_function:
    ; === Prologue ===
    push   %rbp
    mov    %rsp, %rbp
    push   %rbx
    push   %r12
    sub    $0x20, %rsp           ; 分配32字节局部空间

    ; === Body ===
    mov    0x10(%rbp), %rax      ; 第1个参数（%rdi 的备份）
    mov    %rax, -0x8(%rbp)      ; 存入局部变量

    ; === Epilogue ===
    add    $0x20, %rsp
    pop    %r12
    pop    %rbx
    pop    %rbp
    ret
```

> ✅ **帧指针 `%rbp` 可选**：现代编译器常启用 `-fomit-frame-pointer` 优化，直接用 `%rsp` 计算偏移。

## 🏠 三、栈帧布局与内存管理

### 3.1 典型栈帧结构（高地址 → 低地址）

```
高地址
+-----------------------------+
| 调用者栈帧（Caller's frame）|
+-----------------------------+
| 返回地址（由 call 压入）     | ← 8(%rbp)
+-----------------------------+
| 旧的 %rbp（由 push %rbp 保存）| ← (%rbp)
+-----------------------------+
| 保存的 callee-saved 寄存器   | ← -8(%rbp), -16(%rbp)...
+-----------------------------+
| 局部变量                    | ← -24(%rbp)...
+-----------------------------+
| 临时/对齐填充               |
+-----------------------------+
低地址 ← %rsp 指向此处
```

### 3.2 栈操作示例（逐步构建栈帧）

初始状态（调用前）：
```
%rsp → [调用者数据...]
```

`call func` 后：
```
%rsp → [返回地址]
       [调用者数据...]
```

`push %rbp` 后：
```
%rsp → [旧 %rbp]
       [返回地址]
       [调用者数据...]
```

`sub $0x20, %rsp` 后：
```
%rsp → [未初始化局部空间...（32字节）]
       [旧 %rbp]
       [返回地址]
       [调用者数据...]
```

---

### 3.3 Red Zone（红色区域）优化

- **定义**：`%rsp` 下方 **128 字节**（0x80 字节）的区域
- **用途**：**叶子函数**（不调用其他函数）可直接使用，**无需调整 `%rsp`**
- **优势**：减少 `sub/add %rsp` 指令，提升性能
- **限制**：中断/信号处理可能覆盖此区域（但用户态程序通常安全）

```asm
leaf_func:
    mov %rdi, -0x8(%rsp)   ; 安全：在 Red Zone 内
    mov %rsi, -0x10(%rsp)
    ret                    ; 无需调整 %rsp

non_leaf_func:
    sub $0x18, %rsp        ; 必须分配空间（因会 call）
    mov %rdi, (%rsp)
    call other_func
    add $0x18, %rsp
    ret
```

> 📌 Red Zone 仅适用于 **用户态、非内核、叶子函数**。

## 🌐 四、虚拟内存与页表机制

### 4.1 x86-64 虚拟地址空间布局（典型 Linux）

```
0x00007fffffffffff  ← 用户空间上限（canonical address）
+------------------+
| 栈 (Stack)       | ← %rsp 指向，向低地址增长
| ... (动态扩展)    |
+------------------+
| 内存映射区 (mmap)|
| 共享库 (libc.so等)|
+------------------+
| 堆 (Heap)        | ← brk/sbrk 向高地址增长
+------------------+
| BSS 段（未初始化全局变量）|
+------------------+
| Data 段（已初始化全局变量）|
+------------------+
| Text 段（代码）   |
+------------------+
0x0000000000400000  ← 程序入口（如 _start）
0x0000000000000000
```

- **栈与堆之间是“空洞”**，由 OS 动态管理
- **栈通过 page fault 自动扩展**（直到 RLIMIT_STACK 限制）

---

### 4.2 四级页表结构（48 位虚拟地址）

x86-64 使用 **4 级页表** 将虚拟地址映射到物理地址：

```
虚拟地址（48 位有效）：
+----9----+----9----+----9----+----9----+----12----+
|  PML4  |   PDP   |   PD    |   PT    |  Offset  |
| (47-39)| (38-30) | (29-21) | (20-12) | (11-0)   |
+--------+---------+---------+---------+----------+
```

- **PML4**（Page Map Level 4）：顶级页表，由 **CR3 寄存器** 指向
- **PDP**（Page Directory Pointer）
- **PD**（Page Directory）
- **PT**（Page Table）
- **Offset**：页内偏移（4KB 页）

> ✅ 支持 **2MB / 1GB 大页**（通过 PD/PDP 条目直接指向物理页，跳过下级）

---

### 4.3 页表条目（PTE）结构（64 位）

```c
struct page_table_entry {
    uint64_t present    : 1;    // 1 = 页在内存中
    uint64_t rw         : 1;    // 1 = 可写，0 = 只读
    uint64_t user       : 1;    // 1 = 用户态可访问
    uint64_t pwt        : 1;    // Page-level Write Through
    uint64_t pcd        : 1;    // Page-level Cache Disable
    uint64_t accessed   : 1;    // CPU 自动置位（访问过）
    uint64_t dirty      : 1;    // CPU 自动置位（写过）
    uint64_t pat        : 1;    // Page Attribute Table
    uint64_t global     : 1;    // 全局页（TLB 不随 CR3 刷新）
    uint64_t available  : 3;    // OS 可用
    uint64_t frame      : 40;   // 物理页帧号（PFN）
    uint64_t reserved   : 11;   // 必须为 0
    uint64_t nx         : 1;    // No-eXecute（DEP/NX 位）
};
```

- **NX 位**：防止栈/堆代码执行（安全机制）
- **User 位**：区分内核/用户空间访问权限

---

### 4.4 虚拟地址转换过程（伪代码）

```c
phys_addr_t translate(virt_addr_t va, uint64_t cr3_base) {
    // PML4 索引
    uint64_t pml4_idx = (va >> 39) & 0x1FF;
    pml4e_t *pml4 = (pml4e_t*)(cr3_base & ~0xFFF);
    if (!(pml4[pml4_idx] & PRESENT)) page_fault();

    // PDP
    uint64_t pdp_idx = (va >> 30) & 0x1FF;
    pdpe_t *pdp = (pdpe_t*)((pml4[pml4_idx] & ~0xFFF));
    if (!(pdp[pdp_idx] & PRESENT)) page_fault();

    // PD
    uint64_t pd_idx = (va >> 21) & 0x1FF;
    pde_t *pd = (pde_t*)((pdp[pdp_idx] & ~0xFFF));
    if (!(pd[pd_idx] & PRESENT)) page_fault();

    // PT
    uint64_t pt_idx = (va >> 12) & 0x1FF;
    pte_t *pt = (pte_t*)((pd[pd_idx] & ~0xFFF));
    if (!(pt[pt_idx] & PRESENT)) page_fault();

    // 物理地址 = 页帧号 + 页内偏移
    return (pt[pt_idx] & ~0xFFF) | (va & 0xFFF);
}
```

- **TLB（Translation Lookaside Buffer）**：缓存常用 VA→PA 映射，加速访问
- **缺页异常（Page Fault）**：由 OS 处理（分配物理页、更新页表、或终止进程）

## 🔍 五、实际案例分析

### 5.1 `sscanf` 调用分析（来自 Bomb Lab）

```asm
phase_defused:
    lea    0x10(%rsp), %r8     ; 第5参数：字符串缓冲区地址
    lea    0xc(%rsp), %rcx     ; 第4参数：&int2
    lea    0x8(%rsp), %rdx     ; 第3参数：&int1
    mov    $0x402619, %esi     ; 第2参数：格式字符串 "%d %d %s"
    mov    $0x603870, %edi     ; 第1参数：输入字符串地址
    call   __isoc99_sscanf@plt
    cmp    $0x3, %eax          ; 检查是否成功解析3个参数
```

- **寄存器使用完全符合 ABI**
- **栈上变量**：`int1`, `int2`, `buffer[16]` 位于调用者栈帧
- **返回值**：`%eax` = 成功转换的参数个数

### 5.2 栈与虚拟内存交互（C 代码 → 汇编 → 页表）

```c
void a() {
    int x = 42;
    b(x);
}
void b(int y) {
    char buf[64];
    strcpy(buf, "hello");
}
```

执行流程：
1. `a()` 栈帧建立，`x` 存于栈
2. `call b` → 压入返回地址
3. `b()` 栈帧建立，`buf[64]` 分配
4. 若 `%rsp` 越过当前映射页边界 → **page fault**
5. OS 检查是否为合法栈扩展 → 分配新物理页 → 更新页表 → 继续执行
6. 若超出栈限制（如 8MB）→ **SIGSEGV**

## 💡 七、关键概念总结与开发启示

### 7.1 核心原则

| 概念 | 说明 |
|------|------|
| **寄存器共享** | 所有函数共享寄存器，靠 ABI 约定隔离 |
| **栈是逻辑结构** | 由 `%rsp` 管理，物理内存由页表映射 |
| **页表是桥梁** | 虚拟地址 → 物理地址，支持保护、共享、按需分配 |
| **Red Zone 是优化** | 叶子函数可省略栈调整 |

---

### 7.2 常见误区澄清

| 误区 | 正确理解 |
|------|--------|
| “每个函数有自己的寄存器” | ❌ 所有函数共享寄存器，靠保存/恢复实现隔离 |
| “寄存器值保存在页表中” | ❌ 寄存器值保存在 **栈内存** 中 |
| “可以随意使用任何寄存器” | ❌ 必须遵守 **ABI 调用约定** |
| “栈大小固定” | ❌ 栈通过 **page fault 动态增长**（有上限） |
| “虚拟地址 = 物理地址” | ❌ 必须经过 **四级页表转换** |

---

### 7.3 实际开发启示

1. **编写汇编**：严格遵循 System V ABI，否则链接/调用会出错
2. **逆向工程**：通过寄存器使用和栈帧回溯理解程序逻辑
3. **性能优化**：
   - 减少内存访问，多用寄存器
   - 利用 Red Zone 优化叶子函数
4. **调试内存错误**：
   - 栈溢出 → 检查递归/大局部数组
   - 段错误 → 检查指针、页权限（NX、RW）
5. **安全编程**：
   - 栈不可执行（NX 位）
   - 栈保护（Canary）
   - ASLR（地址空间随机化）

## 🎨 附：栈与虚拟内存关系示意图（文字版）

```
高地址 (0x7fff...)
+---------------------+  ← 初始栈顶（如 0x7fffffffe000）
| 栈页 3 (RW, mapped) |
|                     |
|                     |
|                     |
| 栈数据...           |
+---------------------+
| 栈页 2 (RW, mapped) |
|                     |
|        ↑            |
|      %rsp ──────────+ ← 当前栈顶指针
|                     |
|  Red Zone           | ← **128 字节（0x80）安全区**
|  [%rsp - 0x80,      |    叶子函数可直接使用，
|   %rsp - 1]         |    无需调整 %rsp
|                     |
+---------------------+
| 栈页 1 (RW, mapped) |
|                     |
|                     |
+---------------------+
| Guard Page          | ← 未映射页（unmapped）
| (unmapped)          |    访问即触发 SIGSEGV（栈溢出）
+---------------------+
| ... (空洞)          |
+---------------------+
| 堆 (grows up)       |
+---------------------+
低地址
```

- **栈增长**：向低地址，每次 page fault 扩展 1 页（4KB）
- **Guard Page**：防止栈无限增长，保护其他内存区域
