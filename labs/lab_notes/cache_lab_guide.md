## 一、知识热身：缓存基础（带问题的自学路线）

### 1.1 缓存的三个参数

缓存由三个参数描述：
- **S = 2^s**：组（set）的数量
- **E**：每组有多少行（line）
- **B = 2^b**：每行存多少字节（block size）

**手绘练习**：在纸上画出一个 S=4, E=2, B=8 的缓存结构。
它应该看起来像什么？每一行包含哪些字段？

<details>
<summary>思路提示（自己画完再看）</summary>

每一行（cache line）包含三个字段：
- `valid bit`：这行有没有被使用
- `tag`：用来判断是否命中的标识符
- `data`：实际存储的 B 个字节数据

整个缓存 = S 个组 × E 行/组 × (1 + tag bits + B bytes) 每行
</details>

---

### 1.2 地址如何映射到缓存

给定地址位数为 m 位，缓存参数 (s, E, b)：

```
地址的位划分：
|<--- tag bits --->|<--- s bits --->|<--- b bits --->|
|      tag         |   set index    |  block offset  |
```

**思考题1**：假设地址为 64 位，缓存参数 s=4, b=3，那么：
- block offset 用几位表示？
- set index 用几位表示？
- tag 用几位表示？

**思考题2**：下面哪两个地址会映射到**同一个 set**？为什么？
```
地址 A: 0x0012   (二进制: 0000 0000 0001 0010)
地址 B: 0x0022   (二进制: 0000 0000 0010 0010)  
地址 C: 0x0032   (二进制: 0000 0000 0011 0010)
```
（假设 s=2, b=1）

**动手练习**：用 `./csim-ref -v -s 2 -E 1 -b 2 -t traces/yi2.trace` 运行参考模拟器（`-v` 开启详细输出），观察每次访问的 hit/miss 结果，试着手工验证其中 2~3 次访问是否和你的计算一致。

---

### 1.3 命中、缺失、驱逐

三种结果的含义：

| 结果 | 含义 | 代价 |
|------|------|------|
| **hit（命中）** | 要的数据正好在缓存里 | 快 |
| **miss（缺失）** | 数据不在缓存里，从内存取 | 慢 |
| **eviction（驱逐）** | 缺失且该组已满，需要踢掉一行再放入 | 最慢 |

**思考题3**：一次内存访问能同时产生 miss 和 eviction 吗？什么情况下会？

**思考题4**：对于 E=1（直接映射缓存）和 E=4（4路组相联缓存），当两个地址映射到同一组时，会发生什么不同？哪种情况更容易产生 eviction？

---

### 1.4 LRU 替换策略

当一个组已满（E 行都被占用），需要踢走一行时，选择"最近最久没被使用"的那行。

**思考题5**：如何在程序中实现 LRU？考虑这个数据结构：

```c
struct cache_line {
    int valid;
    int tag;
    int lru_counter;  // 这个字段有什么用？
};
```

当一行被访问时，`lru_counter` 应该怎么更新？
要踢走一行时，应该踢走 `lru_counter` 最大还是最小的那行？

**关键决策**：你打算用"全局时钟"（每次访问全局计数器+1）还是"相对排名"来实现 LRU？两种方式各有什么优缺点？

## 二、Part A 引导：实现缓存模拟器

### 2.1 理解任务

你需要实现 `csim.c`，模拟一个缓存的行为，统计命中/缺失/驱逐次数。

**输入**：trace 文件，每行格式为：
```
操作类型 地址,大小
```
例如：
```
I 0400d7d4,8     # 指令加载（忽略）
 L 10,1          # 数据加载（访问一次缓存）
 M 20,1          # 数据修改（相当于加载+存储 = 两次访问）
 S 18,1          # 数据存储（访问一次缓存）
```

**输出**：打印 `hits:X  misses:Y  evictions:Z`，然后调用 `printSummary(hits, misses, evictions)`。

### 2.2 开始前，先设计数据结构

**问题**：如何在 C 中表示整个缓存？

自己先想一想，然后考虑：
1. 缓存需要 S 个组，每组 E 行，每行包含哪些字段？
2. 用二维数组还是动态分配？（提示：S 和 E 是运行时参数，不是编译期常量）
3. 如何初始化缓存（valid 位初始为 0）？

**动手**：先只写出数据结构定义，不写函数体，确认你的设计能表达所需信息。

### 2.3 分步实现建议

**第一步：命令行参数解析**

程序需要接受 `-s`、`-E`、`-b`、`-t`、`-v`、`-h` 参数。

推荐使用 `getopt` 函数（查 `man 3 getopt`）。先跑通参数解析，打印参数确认正确，再往下写。

```bash
./csim -s 4 -E 1 -b 4 -t traces/yi.trace
# 先在这里插入 printf 打印 s=4, E=1, b=4, t=yi.trace 确认解析正确
```

**第二步：读取 trace 文件**

使用 `fscanf` 或 `fgets` 逐行读取，提取操作类型和地址。

注意：操作类型前有可能有空格，`I` 操作没有空格但 `L/S/M` 前有一个空格。建议用 `fscanf(file, " %c %x,%d", &op, &addr, &size)` 解析（注意格式串前的空格）。

**动手验证**：先只解析文件，把每行打印出来，和 trace 文件对比，确保解析正确。

**第三步：实现单次访问函数**

写一个函数 `access_cache(addr)` 模拟一次缓存访问，返回或更新 hit/miss/eviction 计数。

函数内部逻辑：
```
1. 从地址中提取 set_index 和 tag
   （用位运算：set_index = (addr >> b) & ((1 << s) - 1)）
   （tag = addr >> (s + b)）

2. 查找该 set 中是否有 valid=1 且 tag 匹配的行
   - 有 → hit，更新 LRU 计数器
   - 没有 → miss
     - 如果有空行（valid=0）→ 直接装入，更新 LRU
     - 如果没有空行 → eviction，踢走 LRU 最旧的行，再装入
```

**第四步：处理 M 操作**

`M`（modify）等价于一次 `L` 加一次 `S`，也就是对同一地址访问两次。

想一想：第二次访问同一地址时，是必然 hit 吗？为什么？

**第五步：测试和验证**

```bash
# 使用参考模拟器生成正确答案
./csim-ref -s 1 -E 1 -b 1 -t traces/yi2.trace
# 用你的模拟器跑同样参数
./csim -s 1 -E 1 -b 1 -t traces/yi2.trace
# 使用测试脚本
./test-csim
```

**调试建议**：先从最小的 trace 文件（yi2.trace 只有 4 行）开始，手工推算每次访问的预期结果，再和程序对比。

### 2.4 常见陷阱

- **地址是 64 位**：用 `unsigned long` 或 `uint64_t` 存地址，不要用 `int`（32位会截断）。
- **LRU 计数器**：每次任何访问（hit 或 miss）后都要更新该组所有行的 LRU 状态，还是只更新被访问的那行？想清楚再实现。
- **不需要存实际数据**：本题只统计 hit/miss，不需要模拟缓存的数据字段，节省实现复杂度。
- **`I` 操作跳过**：指令加载不访问数据缓存，直接忽略。

## 三、Part B 引导：优化矩阵转置

### 3.1 理解任务

你需要在 `trans.c` 中实现矩阵转置函数：
```c
void transpose_submit(int M, int N, int A[N][M], int B[M][N]);
```

**目标**：最小化缓存缺失次数（miss count）。

**测试的三种矩阵大小**：
- 32×32
- 64×64
- 61×67（非规则大小）

**评分标准**：
- 32×32：miss < 300 得满分
- 64×64：miss < 1300 得满分
- 61×67：miss < 2000 得满分

缓存参数固定：`s=5, E=1, b=5`（即 32 组，直接映射，每行 32 字节）。

### 3.2 热身：分析朴素转置的问题

先运行朴素实现（直接按定义转置）：

```bash
./test-trans -M 32 -N 32
```

**思考题6**：朴素转置大概产生多少次 miss？你能估算吗？

分析思路（引导，不是答案）：
1. 矩阵 A 是 32×32 的 int 数组，每个 int = 4 字节，一行有 32 个元素 = 128 字节
2. 缓存每行（block）= 32 字节 = 8 个 int
3. 转置时，读 A[i][j] 是**按行**访问（空间局部性好），写 B[j][i] 是**按列**访问（空间局部性差）
4. 因为 E=1（直接映射），A 和 B 的某些行可能**映射到同一个 set**，导致互相驱逐

**动手**：用 `-v` 参数观察某几行的 miss 情况：
```bash
# 在 trans.c 里添加一个简单的朴素实现
# 然后观察 csim-ref 的详细输出
./csim-ref -v -s 5 -E 1 -b 5 -t trace.f0
```

### 3.3 核心优化思路：分块（Blocking）

分块的核心思想：**把矩阵分成小块，每次处理一块，让这一块在被用完之前一直待在缓存里，避免被驱逐**。

**思考题7**：对于 32×32 的矩阵，如果使用 8×8 的分块（block size = 8），每处理一个 8×8 的小块：
- 需要读多少个 A 的缓存行？
- 这 8 行数据加起来多大？缓存容量够不够放下？

（缓存总容量 = S × E × B = 32 × 1 × 32 = 1024 字节 = 256 个 int）

**思考题8**：分块之后，朴素转置中"按列写 B"的问题有没有改善？想一想对于一个 8×8 的小块，写 B 的访问模式是什么？

**动手实验**：先实现一个 8×8 分块的版本，测试 miss 数量，看看比朴素版本改善了多少。

### 3.4 32×32 矩阵的特殊问题

即使分块后，还有一个特殊情况需要处理：**对角线上的分块**。

**思考题9**：为什么对角线上（A 和 B 的同一位置）的分块会有额外的 miss？

提示：A[i][j] 和 B[j][i] 对于 i==j 时，他们的内存地址有什么关系？在直接映射缓存（E=1）中，如果两个地址映射到同一个 set 会发生什么？

**引导方向**：可以考虑利用**局部变量（临时变量）**来减少对 B 的写操作次数，从而降低 A 和 B 之间的缓存冲突。想一想：临时变量存在寄存器里，不占缓存行，能不能利用这个特点？

### 3.5 64×64 矩阵：更难的挑战

64×64 矩阵比 32×32 更难优化，原因在于缓存容量相对更小。

**思考题10**：64×64 矩阵，每行 64 个 int = 256 字节。缓存有 32 行，每行 32 字节，总计 1024 字节。

如果还用 8×8 分块，一个 8×8 块读 A 需要 8 个缓存行，这 8 个缓存行会不会映射到同一个 set？

（提示：64 列 × 4 字节/int = 256 字节/行，缓存 32 字节/行，所以矩阵的每一行跨越 8 个缓存行。矩阵的第 0 行和第 4 行的起始地址相差 4×256=1024 字节 = 32 个缓存行... 映射到的 set index 相差多少？）

**引导方向**：64×64 矩阵需要更精细的分块策略，可以尝试 4×4 分块，或者更巧妙的 8×8 + 内部细分策略。关键思路是：**在一次处理 8 列数据时，把 B 的 8 行"预先存到 A 的缓存行中"来减少 B 的 miss**。这比较难想到，建议先实现 4×4 分块达到基本分数，再尝试更优的方案。

### 3.6 61×67 矩阵：非规则大小

这个大小的矩阵不是 2 的幂次，冲突问题没有 64×64 那么严重。

**思考题11**：对于非规则矩阵，分块时需要处理边界情况（最后几行/列不满一块的情况）。你的代码如何处理这种情况？
