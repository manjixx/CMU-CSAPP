## 五大现实（Five Realities）

### Reality 1：整数不是数学意义上的整数，浮点数不是实数

> **Great Reality 1: Ints are not Integers, Floats are not Reals**

**示例 1**：$x^2 \geq 0$？
- 浮点数：**总是成立** ✓
- 整数：**不成立** ✗
  - `50000 * 50000 = 2500000000`（超过 32 位 int 上限 ~2.1×10⁹，溢出为负数）
  - `300 * 400 * 500 * 600`（类似溢出）

**示例 2**：$(x + y) + z = x + (y + z)$？
- 无符号整数和有符号整数：**总是成立** ✓（模运算满足结合律）
- 浮点数：**不成立** ✗
  - $(10^{20} + (-10^{20})) + 3.14 = 0 + 3.14 = 3.14$
  - $10^{20} + ((-10^{20}) + 3.14) = 10^{20} + (-10^{20}) = 0$（3.14 被淹没）

**深层含义**：
- 计算机算术**不产生随机值**，有重要的数学性质，但不同于数学中的整数/实数
- 整数运算满足"**环（Ring）**"属性：交换性、结合性、分配性（模 $2^w$ 的世界）
- 浮点运算满足"**偏序（Ordering）**"属性：单调性、符号值（IEEE 754 规范）
- **不能**将普通数学性质直接套用到计算机数值上

> **学习意义**：第 2 章《信息的表示与处理》

### Reality 2：你必须懂汇编

> **Great Reality 2: You've Got to Know Assembly**

现实是：你很可能**永远不会手写**汇编程序。但理解汇编是**机器级执行模型**的关键：

**为什么需要读懂汇编**：

| 场景 | 具体用途 |
|------|---------|
| 调试 | 当程序崩溃时，只有汇编能揭示实际发生了什么 |
| 性能调优 | 了解编译器做了什么、没做什么；找到性能低下的根源 |
| 系统软件实现 | 编译器以机器码为目标；OS 必须管理进程状态 |
| 安全 | 创建或防御恶意软件，理解缓冲区溢出等漏洞 |

**x86-64** 是本课程汇编语言的首选（最主流的服务器/PC 架构）。

> **学习意义**：第 3 章《机器级程序表示》

### Reality 3：内存很重要——随机存取内存是不完美的抽象

> **Great Reality 3: Memory Matters — Random Access Memory Is an Unphysical Abstraction**

**三个关键问题**：

1. **内存并非无限**：必须被分配和管理；许多应用程序是内存主导的（memory-bound）
2. **内存引用错误极其有害**：C/C++ 不提供任何内存保护
3. **内存性能不均匀**：高速缓存（Cache）和虚拟内存（VM）可以极大地影响程序性能

**内存引用 Bug 示例**：

```c
typedef struct {
    int a[2];
    double d;
} struct_t;

double fun(int i) {
    volatile struct_t s;
    s.d = 3.14;
    s.a[i] = 1073741824; /* 可能越界 */
    return s.d;
}

/* 实际结果（取决于编译器和平台）：
 * fun(0) → 3.14       正常
 * fun(1) → 3.14       正常
 * fun(2) → 3.1399998664856  开始破坏 d 的低位
 * fun(3) → 2.00000061035156 破坏 d 的高位
 * fun(4) → 3.14       可能踩到了其他内存
 * fun(6) → Segmentation fault
 */
```

`a[2]` 和 `a[3]` 访问到了结构体 `d` 的内存！这是典型的数组越界覆盖相邻内存的案例。

**内存引用错误的危害**：
- C/C++ 无边界检查：数组越界、无效指针、`malloc/free` 滥用
- Bug 的影响可能**延迟出现**：损坏的对象在逻辑上与被访问的对象无关
- 修复建议：
  - 使用更安全的语言（Java、Python、Rust）
  - 理解可能发生的干扰，编写防御性代码
  - 使用检测工具：**Valgrind**、**AddressSanitizer**（`-fsanitize=address`）

> **学习意义**：第 6 章《存储器层次结构》、第 9 章《虚拟内存》

### Reality 4：性能不仅仅取决于算法复杂度

> **Great Reality 4: There's More to Performance than Asymptotic Complexity**

**常数因子也很重要**（Constant factors matter too！）：

```c
/* 2.0 GHz Intel Core i7 Haswell 实测 */

/* 行优先访问 (ij) — 4.3ms */
void copyij(int src[2048][2048], int dst[2048][2048]) {
    int i, j;
    for (i = 0; i < 2048; i++)
        for (j = 0; j < 2048; j++)
            dst[i][j] = src[i][j];  // 顺序访问，cache 友好
}

/* 列优先访问 (ji) — 81.8ms */
void copyji(int src[2048][2048], int dst[2048][2048]) {
    int i, j;
    for (j = 0; j < 2048; j++)
        for (i = 0; i < 2048; i++)
            dst[i][j] = src[i][j];  // 跳跃访问，cache 不友好
}
```

**相同算法复杂度（O(n²)），性能差 19 倍！** 原因是 C 数组按行优先（row-major）存储，跳跃访问导致大量 Cache Miss。

**性能优化要求**：
- 理解程序如何编译和执行
- 理解如何衡量程序性能并识别瓶颈
- 在不破坏代码模块化的前提下改进性能
- 必须在多个层次优化：**算法 → 数据表示 → 过程 → 循环 → 指令**

> **学习意义**：第 5 章《优化程序性能》、第 6 章《存储器层次结构》

### Reality 5：计算机不只是执行程序

> **Great Reality 5: Computers Do More Than Execute Programs**

现代计算机需要：
- **I/O**：与用户、磁盘、网络等交互
- **网络通信**：通过网络与其他机器交互

这引入了一系列**系统级问题**：
- **并发（Concurrency）**：自主进程的并发操作
- **可靠性（Reliability）**：应对不可靠的传输媒体
- **跨平台兼容性（Portability）**：不同硬件/OS 之间的通信
- **性能瓶颈（Performance）**：网络延迟与带宽限制

> **学习意义**：第 8 章《异常控制流》、第 10 章《系统级 I/O》、第 11 章《网络编程》、第 12 章《并发编程》
