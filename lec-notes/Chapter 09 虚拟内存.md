## 9.0 本章核心问题

> **为什么每个进程都以为自己独占整个内存空间，而实际运行时却互不干扰？**

虚拟内存（VM）是操作系统与硬件共同提供的核心抽象，它解决三个根本问题：

1. **缓存**：物理内存（DRAM）作为磁盘（虚拟地址空间）的缓存，实现内存远大于物理内存的幻觉。
2. **管理**：简化内存分配与链接/加载机制，每个进程拥有独立的统一地址空间。
3. **保护**：隔离进程，防止非法访问他人或内核内存。

---

## 9.1 物理与虚拟寻址

| 寻址方式 | 描述 |
|---------|------|
| **物理寻址（PA）** | CPU直接用物理地址访问内存，早期嵌入式/单片机常用 |
| **虚拟寻址（VA）** | CPU生成虚拟地址，由MMU翻译为物理地址后访问内存 |

**MMU（Memory Management Unit）**：CPU 片上硬件，负责虚拟地址→物理地址的翻译，依赖页表（存放在内存中）。

---

## 9.2 VM 作为缓存工具（§9.3）

### 核心模型

将虚拟内存（磁盘上的虚拟地址空间）视为以**页（Page）**为单位的缓存：

- **虚拟页（VP, Virtual Page）**：固定大小，通常 **4KB**，是 VM 的基本单元
- **物理页（PP, Physical Page）/ 页帧（Page Frame）**：DRAM 中的等大块

**虚拟页的三种状态**：

| 状态 | 描述 |
|------|------|
| 未分配（Unallocated） | 尚未创建，不占磁盘空间 |
| 已缓存（Cached） | 已加载到物理内存中 |
| 未缓存（Uncached） | 已分配但仍在磁盘，未加载到内存 |

### 为什么 DRAM 缓存不使用组相联/直接映射？

DRAM 缓存缺页（page fault）惩罚极高（需磁盘I/O，约 **100万倍** 于内存访问），因此：
- 采用**全相联**（任意虚拟页可映射到任意物理页）
- 采用**写回（write-back）** 而非写直达
- 使用精巧的替换策略（LRU 近似）

### 页表（Page Table）

每个进程都有一张**页表**，存放在内核内存中，由操作系统维护。

**页表结构**（§9.3.2）：
- 是一个数组，索引为**虚拟页号（VPN, Virtual Page Number）**
- 每个表项称为 **PTE（Page Table Entry）**
- PTE 包含：**有效位（valid bit）** + **物理页号（PPN）** 或磁盘地址

```
虚拟地址结构：
┌─────────────────┬────────────────┐
│  VPN (虚拟页号)  │  VPO (页内偏移) │
└─────────────────┴────────────────┘
            ↓ 查页表
┌─────────────────┬────────────────┐
│  PPN (物理页号)  │  VPO (页内偏移) │
└─────────────────┴────────────────┘
         = 物理地址（PA）
```

VPO 与 PPO（Physical Page Offset）长度相同（均为 log₂(页大小) 位）。

### 缺页（Page Fault）

当访问一个未缓存（valid=0）的虚拟页时触发：

1. CPU 产生缺页异常
2. 内核调用**缺页处理程序**
3. 选择一个**牺牲页（victim page）**，若已修改则写回磁盘
4. 将所需页从磁盘调入该物理页帧
5. 更新 PTE，重新执行触发缺页的指令

**按需调页（Demand Paging）**：只有在访问时才加载页面，这是 VM 高效的核心机制。

**抖动（Thrashing）**：工作集（working set）超过物理内存，导致频繁缺页，性能急剧下降。

## 9.3 VM 作为内存管理工具（§9.4）

每个进程拥有**独立的虚拟地址空间**，对应独立的页表。这带来：

- **简化链接**：每个进程代码段都从同一虚拟地址（如 `0x400000`）开始，链接器无需关心物理位置
- **简化加载**：`exec` 只需在页表中建立虚拟页→文件块的映射，实际数据按需加载
- **简化共享**：多进程共享内核代码/数据、共享库（如 libc）时，只需将各自页表的相应 PTE 指向同一物理页
- **简化内存分配**：`malloc` 申请的虚拟页可分散映射到任意物理页，不需要物理上连续

---

## 9.4 VM 作为内存保护工具（§9.5）

在 PTE 中增加**权限位**：

| 权限位 | 含义 |
|--------|------|
| SUP | 是否需要内核态（supervisor mode）才能访问 |
| READ | 可读 |
| WRITE | 可写 |
| EXEC | 可执行 |

若违反权限，MMU 触发**保护故障（protection fault）**，内核发送 `SIGSEGV`（段错误）给进程。

> **实践意义**：这是 W^X（写不可执行）安全策略的硬件基础，防御栈溢出执行 shellcode。

## 9.5 地址翻译机制（§9.6）

### 基本流程（§9.6.1）

```
CPU → 虚拟地址(VA) → MMU → 查页表(PTBR指向) → 物理地址(PA) → 内存/Cache
```

- **PTBR（Page Table Base Register）**：CR3寄存器，指向当前进程页表基址
- 命中（valid=1）：直接返回 PA
- 缺页（valid=0）：触发缺页异常

### TLB（Translation Lookaside Buffer，§9.6.2）

页表访问需要**额外一次内存访问**，成本高。TLB 是 MMU 内的小型**全相联缓存**，缓存最近用到的 PTE。

```
TLB命中：VA → MMU → TLB（1个周期） → PA（无需访问内存页表）
TLB缺失：VA → MMU → TLB miss → 访问内存页表 → 更新TLB → PA
```

**TLB 刷新**：上下文切换时，需无效化 TLB（或使用 ASID 区分进程）。

### 多级页表（§9.6.3）

32位地址空间需要 4MB 页表（2²⁰ × 4B），64位则不可接受。解决方案：**多级页表**。

以二级页表为例（Intel x86-64 使用四级）：

```
虚拟地址 = VPN1 | VPN2 | VPO
               ↓
一级页表（Page Directory）：由 VPN1 索引 → 二级页表基址
               ↓
二级页表：由 VPN2 索引 → PPN
               ↓
PA = PPN | VPO
```

**关键优化**：若一级 PTE 无效，对应整块二级页表无需存在，节省大量内存。

## 9.6 案例：Intel x86-64 地址翻译（§9.7）

### 地址空间规格

| 规格 | 参数 |
|------|------|
| 虚拟地址位数 | 48位（符号扩展到64位，高16位=第47位） |
| 物理地址位数 | 52位（实际当前 CPU 约 40–48位） |
| 页大小 | 4KB（标准）/ 2MB / 1GB（大页） |
| 每级页表大小 | 4KB（512个 × 8B 的 PTE） |

### 四级页表结构（PML4 → PDPT → PD → PT）

```
48位虚拟地址结构：
┌───────┬───────┬───────┬───────┬──────────────┐
│ PML4  │ PDPT  │  PD   │  PT   │    偏移VPO   │
│ 9 bit │ 9 bit │ 9 bit │ 9 bit │    12 bit    │
└───────┴───────┴───────┴───────┴──────────────┘

翻译过程（CR3 = PML4 基址）：
CR3 ──┐
      ↓
PML4[VPN[3]] ──→ PDPT 基址
                      ↓
               PDPT[VPN[2]] ──→ PD 基址
                                    ↓
                             PD[VPN[1]] ──→ PT 基址
                                                ↓
                                        PT[VPN[0]] ──→ PPN
                                                           ↓
                                               PA = PPN | VPO（12位）
```

**每级 9 位 → 512 个表项；4级共索引 2³⁶ 个页，虚拟空间 = 2⁴⁸ B = 256TB**

### Intel Core i7 TLB 结构

| TLB 层级 | 大小 | 关联度 | 延迟 |
|---------|------|--------|------|
| L1 指令 TLB | 128 项 | 4路 | 1 周期 |
| L1 数据 TLB | 64 项 | 4路 | 1 周期 |
| L2 统一 TLB（STLB） | 1024 项 | 8路 | ~6 周期 |

**完整翻译流程（有 TLB）**：

```
虚拟地址 VA
    │
    ├── TLB 命中（L1 TLB，~1周期）→ 直接得到 PA
    │
    └── TLB 缺失
            │
            ├── L2 TLB 命中（~6周期）→ 更新 L1 TLB → PA
            │
            └── 硬件页表遍历（Page Table Walk）
                    │  访问4级页表（最多 4 次内存访问）
                    └── 更新 STLB → PA
```

**上下文切换时 TLB 处理**：`mov cr3, reg` 会刷新整个 TLB；现代处理器使用 **PCID（Process Context ID）** 避免全刷。

## 9.7 内存映射（Memory Mapping，§9.8）

Linux 将**文件或匿名对象**映射到虚拟地址空间区域，实现统一的 VM 机制。

```c
void *mmap(void *start, size_t length, int prot, int flags, int fd, off_t offset);
```

| 参数 | 说明 |
|------|------|
| `prot` | `PROT_READ/WRITE/EXEC` |
| `flags` | `MAP_SHARED`（修改写回文件）/ `MAP_PRIVATE`（写时复制COW） |
| `fd` | 映射的文件描述符，`-1`表示匿名映射 |

### 写时复制（Copy-On-Write，COW）

`fork()` 后父子进程共享物理页，页表项标记为只读。任一进程写入时触发保护故障，内核复制该页后再写。这使 `fork()` 的开销从 O(内存大小) 降为 O(1)。

### exec 的实现

`execve` 不复制数据，而是：
1. 删除当前虚拟区域
2. 建立新的虚拟区域映射到可执行文件的各段
3. 映射共享库
4. 将 PC 设置为入口点

## 9.8 动态内存分配（§9.9）

### 堆与分配器

- **堆（heap）**：从 BSS 段末尾（`brk`指针）向高地址增长
- **分配器（allocator）**：管理堆的代码，如 `malloc/free`

```c
#include <stdlib.h>
void *malloc(size_t size);  // 返回对齐的内存块，失败返回NULL
void free(void *ptr);        // ptr必须是malloc返回的指针
void *calloc(size_t n, size_t size);  // 清零
void *realloc(void *ptr, size_t newsize);
```

### 分配器目标与约束

**目标**：最大化**吞吐量**（ops/sec）且最大化**内存利用率**（最小化碎片）。

**约束**：
- 不能控制请求顺序
- 必须立即响应请求
- 块必须对齐（x86-64：16字节对齐）
- 只能操作堆内存

### 碎片（Fragmentation）

| 类型 | 描述 |
|------|------|
| **内部碎片** | 分配的块大于请求（对齐/头部开销），浪费在块内部 |
| **外部碎片** | 空闲内存总量足够，但没有单一连续块满足请求 |

### 隐式空闲链表（Implicit Free List，§9.9.6）

每个块的头部（header）编码**块大小 + 分配位**：

```
┌──────────────────────────────────┬───┐
│         块大小（字节）             │ a │  ← 头部（4字节）
├──────────────────────────────────┴───┤
│              有效载荷                 │
│         (+ 可能的对齐填充)            │
└──────────────────────────────────────┘
```

- 块大小编码在高位，最低位（size 总是8的倍数，低3位为0）用作分配位 `a`
- **遍历**：从堆起点按块大小跳跃，直到特殊终止块

**放置策略**：
- **首次适配（First Fit）**：从头扫描，找到第一个足够大的空闲块
- **下次适配（Next Fit）**：从上次位置继续扫描（减少外部碎片，但利用率差）
- **最佳适配（Best Fit）**：扫描全部，取最接近的（利用率好，速度慢）

**合并（Coalescing）**：释放块后与相邻空闲块合并，防止假性外部碎片。

**边界标记（Boundary Tag，§9.9.11）**：在块末尾添加与头部相同的脚部（footer），允许 O(1) 向前合并。

### 显式空闲链表（Explicit Free List）

空闲块内部存储 `prev/next` 指针，构成双向链表，跳过已分配块，分配效率 O(空闲块数)。

### 分离空闲链表（Segregated Free List）

按大小分类，每类维护独立链表：
- **简单分离存储**：每类固定大小，内部碎片大，分配快
- **分离适配（如 `ptmalloc`/`jemalloc`）**：每类按大小范围，兼顾速度与利用率

## 9.9 垃圾回收（§9.10）

**标记-清除（Mark & Sweep）** 基本思想：
1. **标记阶段**：从根集合（栈、全局变量中的指针）出发，DFS遍历标记所有可达块
2. **清除阶段**：扫描堆，未标记的块调用 `free`

C 语言实现**保守垃圾回收**：无法区分整数与指针，将所有看起来像堆指针的值都当作指针处理（可能保留实际不可达的块）。

## 9.10 常见内存错误（§9.11）

| 错误类型 | 示例 | 后果 |
|---------|------|------|
| **解引用坏指针** | `scanf("%d", val)` 而非 `&val` | 段错误或静默数据损坏 |
| **读取未初始化内存** | `malloc` 后直接读 | 随机值，难以复现的Bug |
| **栈缓冲区溢出** | `gets()` 无边界检查 | 覆盖返回地址，安全漏洞 |
| **假设指针与整数等大** | 64位下 `int p = malloc(...)` | 指针被截断 |
| **Off-by-one 错误** | `for (i=0; i<=n; i++)` 越界 | 堆元数据损坏 |
| **引用已释放内存（悬空指针）** | `free(p); *p = x;` | 未定义行为 |
| **重复释放** | `free(p); free(p);` | 堆元数据损坏，崩溃 |
| **忘记释放（内存泄漏）** | 循环内 malloc 无 free | 程序内存持续增长 |

> **工具推荐**：Valgrind、AddressSanitizer（`-fsanitize=address`）可检测大多数上述错误。

## 9.12 要点速览

1. **虚拟内存 = 缓存 + 管理 + 保护**：三位一体，DRAM 是磁盘数据的缓存，页表是索引。
2. **TLB 是性能关键**：几乎所有内存访问都依赖 TLB 命中；地址翻译本身就在关键路径上。
3. **COW 使 fork 变轻量**：父子进程延迟复制物理页，写时才真正分配。
4. **碎片是分配器的核心挑战**：隐式链表简单，分离链表（jemalloc）是工业级解法。
5. **内存错误难以调试**：悬空指针、缓冲区溢出常在触发点之后才暴露，善用 ASan/Valgrind。
